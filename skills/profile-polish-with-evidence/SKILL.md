# Profile polish that survives a background check

## Order of work
1. Read the CURRENT state first, read-only: `gh api user`, `gh repo list`, each public README; LinkedIn pages through browser automation (the main page lazy-loads and hides About; the edit form shows it); the existing resume source.
2. Cross-check every number against its source (README tables, benchmark logs, notes) BEFORE writing it. Typical finds: a grade on the resume that disagrees with the record (leave it out and flag it), a linked repo name that does not exist, dates that differ between resume and LinkedIn, a headline count that hides how many items are still pending, a speed claim resting on an unsettled measurement.
3. Voice: direct, concrete, numbers only when verified, lead with who and what is wanted, no "excited to share".
4. Keep claims to what is TRUE TODAY: a training goal is not a result.

## What worked
- Repo metadata: `gh repo edit OWNER/REPO --description "..." --homepage URL --add-topic t`.
- Portfolio: one static `index.html`, system fonts, light/dark via CSS variables, one measured number per project, checked in both themes.
- Resume: keep the template, edit the .tex, compile, render to PNG and look at it; keep to one page.
- Reviewers: send other models public-only files with contact details and grades removed, plus a FACTS.md listing the only verified facts. Adopt precision fixes; reject suggestions that change facts.

## Blocks (do not work around; hand over paste-ready text instead)
- GitHub name/bio need the `user` token scope: the user runs `! gh auth refresh -h github.com -s user`. Pinned repos have no REST API (browser automation can do it; verify with GraphQL `user.pinnedItems`).
- LinkedIn edits may be denied after the first few as unrequested commits in a connected app. "Delete skill" cannot be undone. Always decline "notify your network".
- Pushing private repos needs an explicit instruction.
- Never send private notes to reviewer models.

## GitHub profile README that does not look like a resume
- Draw the profile as SVG assets generated by ONE script (hero, stat strip, equal-size project cards, chips, link buttons). Monospace only (character width about 0.62 x font size) so wrapping is computable.
- Pick one grid width and size every asset to it; inline images in `<p align="center">` instead of tables (table padding breaks the edges).
- Preview without github.com: a local HTML mock screenshotted with headless Chrome (`--headless=new --window-size=930,1640 --screenshot=...`).
- Looping SVG animation must show a finished state on the FIRST frame (static renderers hide `opacity:0` starts): drive it with one CSS cycle and negative `animation-delay`.

## LinkedIn through browser automation
- Text areas are DIV textboxes: `form_input` fails; click, select all, delete, type, then read back with JavaScript before Save.
- Typeaheads: type, list `[role=option]`, click the exact text match (the first option can be wrong).
- Saving the intro form re-submits its "current position" dropdown: reread the top card after any headline edit.
- Do not put unpublished research numbers on LinkedIn.
